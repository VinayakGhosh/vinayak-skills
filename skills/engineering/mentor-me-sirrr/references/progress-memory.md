# Optional Progress Memory

Use persistent progress only for a longer onboarding or growth path and only after explicit learner permission.

## Permission and location

Keep progress in session memory by default. Before writing a record:

1. explain what will be recorded and why it helps;
2. ask the learner to approve the location;
3. warn when that location is inside version control and may expose personal learning notes;
4. honor a request for session-only learning without repeated prompts.

Do not upload, publish, commit, or share progress without separate explicit permission.

## Lightweight record

Record only information that makes a future session meaningfully better:

- repository identity and target ref;
- current mode and topic;
- familiarity with the language, repository, and system concepts when volunteered;
- preferred explanation depth or format;
- concepts introduced and evidence anchors explored;
- learner questions and unresolved gaps;
- optional teach-back evidence;
- the mentor cursor: current rung, anchor, and concrete next step.

Keep self-reported confidence separate from demonstrated understanding. Material shown is not proof of mastery. Record neutral observations rather than labels about intelligence or ability, and exclude secrets or unrelated personal information.

## Resume

At the next session, verify that the record belongs to the current repository and explain briefly which ref it describes. If the code has changed materially, preserve the prior record as historical context and offer a cognitive reload instead of treating it as current truth.

Resume with a concise recap, one unresolved question if relevant, and the saved next step. Do not repeat full onboarding unless the learner asks or the system map is no longer trustworthy.
