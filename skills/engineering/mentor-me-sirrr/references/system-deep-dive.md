# System Deep Dive

Use this mode for a focused question about one component, workflow, architectural choice, or domain concept.

## Outcome

The developer can explain the topic's responsibility, place in the larger system, main flow, evidence anchors, and the most relevant failure behavior.

## Teaching path

1. State the practical problem the topic solves in everyday language.
2. Locate it in the repository-level system map.
3. Identify its inputs, outputs, dependencies, and consumers.
4. Show the happy-path flow before exceptions.
5. Introduce the real technical vocabulary with immediate definitions.
6. Walk through one focused implementation anchor and one relevant test.
7. For medium or large topics, explain what can fail and where to inspect first.

Use a visual when three or more relationships or a sequence would be harder to follow in prose. Preserve the mentor cursor while answering side questions, then return to the selected topic and next anchor.

Prefer causal explanations: connect a design decision to the behavior it enables or prevents. When evidence cannot establish the original motivation, label the explanation as inference instead of presenting it as historical fact.
